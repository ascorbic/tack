Tack runs as **one Cloudflare Worker** on your account, with a **GitHub App you own**. There's no hosted Tack: every instance is someone's own.

You'll need:

- a Cloudflare account
- a GitHub account (and, if your team's repositories belong to an organisation, to be able to create GitHub Apps for it)
- Node.js 22 or later and pnpm 10, to deploy from your machine

## What gets deployed

Everything is declared in [`cloudflare.config.ts`](https://github.com/ascorbic/tack/blob/main/cloudflare.config.ts), read by the [`cf` CLI](https://www.npmjs.com/package/cf). There's no Wrangler configuration.

- **A Worker** named `tack`, serving the app's static files and its API.
- **Four Durable Objects**, all with SQLite storage: one per board, one per repository, and two singletons (the instance's GitHub App, users and sessions; and the board index).
- **A cron trigger**, every ten minutes, that asks GitHub to redeliver webhooks that failed to arrive.
- **Workers Logs**, for [observability](/self-hosting/observability/).
- **Secrets**: `TACK_SECRET`, and two optional ones. See [Secrets](#secrets).

## Deploy

<Steps>

1. **Get the code.** Fork [ascorbic/tack](https://github.com/ascorbic/tack) (so you can deploy from Workers Builds and pull in updates), and clone it.

   ```sh
   git clone https://github.com/<you>/tack.git
   cd tack
   pnpm install
   ```

2. **Deploy the Worker.** Either from your machine:

   ```sh
   pnpm exec cf auth login   # or set CLOUDFLARE_API_TOKEN
   pnpm run deploy
   ```

   `pnpm run deploy` builds Tack and deploys it with `cf deploy`. Note the `run`: `pnpm deploy` is a different, built-in pnpm command.

   Or, better, connect your fork to [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/) in the Cloudflare dashboard, so every push to `main` deploys:
   - deploy command for `main`: `pnpm run deploy`
   - deploy command for other branches: `pnpm run deploy:preview`, which gives each branch a [Preview](#previews) with its own URL

3. **Choose the address you'll keep.** The GitHub App is created for the address you set it up on: its sign-in callback and webhook URL point there. If you'll use a custom domain, add it to the Worker now, and do the rest from that domain rather than `workers.dev`.

4. **Set `TACK_SECRET`.** Generate a long random value, and add it as a secret on the Worker:

   ```sh
   openssl rand -base64 32
   pnpm exec cf workers secrets update TACK_SECRET
   ```

   Or in the dashboard: Workers & Pages → tack → Settings → Variables and secrets. Keep it safe, and **don't change it**: it encrypts the GitHub App's credentials and everyone's stored tokens, and signs sessions.

5. **Create the GitHub App.** Visit `/setup` on your instance straight away, and follow [Set up the GitHub App](/self-hosting/github-app/). Whoever completes setup becomes the instance's first admin.

6. **Install the app** on the repositories you plan with, and **decide who can use the instance**. See [Install on repositories](/self-hosting/github-app/#install-on-repositories) and [Who can use it](/self-hosting/access/).

</Steps>

:::caution[Do setup straight away]
Until setup is complete, `/setup` is open to anyone who can reach your instance, and whoever completes it becomes the admin. Set `TACK_SECRET` and run setup as soon as you've deployed.
:::

## Secrets

| Secret                  | Needed           | What it does                                                                                                                                                                                                    |
| ----------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TACK_SECRET`           | Yes, for sign-in | Signs session cookies, and encrypts every stored credential (the app's private key and secrets, installation tokens, people's GitHub tokens). Without it, sign-in and setup are off and boards work anonymously |
| `GITHUB_WEBHOOK_SECRET` | No               | A second webhook secret, tried after the one the app was created with. For apps set up by hand, and for sending test webhooks locally                                                                           |
| `GITHUB_TOKEN`          | No               | A GitHub token for reading public repositories without the app, so they're not limited to GitHub's anonymous rate limit. Never used for writes                                                                  |

## Previews

Workers Builds deploys a Preview for each branch other than `main`, each with its own URL and its own, empty Durable Objects. Previews get no secrets, so there's no sign-in or setup there ("Previews never get secrets, so boards there are guest-only"): boards work anonymously, cards are fetched without a token, and no webhooks reach them.
